## 🏗 Стек технологий

- **Фреймворк**: [FastAPI](https://fastapi.tiangolo.com/) (асинхронный).
- **База данных**: PostgreSQL.
- **ORM**: [SQLAlchemy 2.0](https://docs.sqlalchemy.org/) (Async).
- **Миграции**: [Alembic](https://alembic.sqlalchemy.org/).
- **Валидация данных**: [Pydantic v2](https://docs.pydantic.dev/).
- **Аутентификация**: [FastAPI-Users](https://fastapi-users.github.io/fastapi-users/).
- **Кэширование**: Redis.
- **Шаблонизатор**: Jinja2 (для e-mail и простых страниц).

## 📂 Структура проекта (папка `backend/`)

Проект следует многослойной архитектуре для изоляции ответственности:

### 1. `api/` — Транспортный уровень
Содержит роутеры и определения эндпоинтов.
- **`api_v1/`**: Основная версия API.
- **`dependencies/`**: Зависимости FastAPI (DI), такие как доступ к бд, redis, текущий пользователь.
- **`webhooks/`**: Обработчики внешних событий.

### 2. `crud/` — Слой бизнес-логики (Service/Repository)
**Критически важное правило**: Вся бизнес-логика должна находиться здесь. Роутеры в `api/` лишь вызывают функции из `crud/`. Это обеспечивает тестируемость и чистоту кода.

### 3. `core/` — Ядро системы
- **`models/`**: SQLAlchemy модели (сущности базы данных).
- **`schemas/`**: Pydantic схемы для валидации входящих данных и формирования ответов.
- **`authentication/`**: Настройка системы входа, JWT-токенов и прав доступа.
- **`config.py`**: Управление настройками через переменные окружения.

### 4. Другие папки
- **`alembic/`**: История изменений схемы базы данных.
- **`tests/`**: Набор автоматических тестов (функциональные, интеграционные, стресс-тесты).
- **`utils/`**: Вспомогательные функции общего назначения.
- **`mailing/`**: Логика отправки уведомлений.
- **`middlewares/`**: Промежуточные слои (логирование, сжатие GZip и др.).

## 🛠 Ключевые правила разработки

1. **Никакого хардкода**: Все настройки, секреты и внешние URL должны быть в `core/config.py` и передаваться через `.env`.
2. **Асинхронность**: Используйте `async`/`await` для всех операций ввода-вывода (БД, Redis, HTTP-запросы).
3. **Логика в CRUD**: Если вам нужно добавить условие, расчет или проверку прав — делайте это в `crud/`.
4. **Типизация**: Обязательное использование Type Hints для всех функций и аргументов.
5. **Миграции**: Любое изменение в `core/models/` должно сопровождаться новой миграцией Alembic.

## 📛 Правила именования (Naming Conventions)

Для поддержания единообразия в проекте используйте следующие соглашения:

### 🔹 Модели (SQLAlchemy)
- Названия в **единственном числе**
- PascalCase

Пример:
```python
class User(Base):
    ...
``` 
### Схемы (Pydantic)
- Названия в **единственном числе**
- EntityAction

Пример: 
```python 
UserBase
UserCreate
UserUpdate 
UserRead
```

### Crud-функции
Использовать префиксы: 
`
get_
create_
update_
delete_
`

## 🔐 Аутентификация и права доступа

Для работы с пользователями используется `FastAPI-Users`. 
- Токены хранятся в БД (Access Tokens).
- Для проверки прав используются встроенные зависимости: `current_active_user`, `current_active_superuser`.

## 🚀 Производительность

- **Кэширование**: Ответы на тяжелые запросы (например, каталог товаров) кэшируются в Redis.
- **Оптимизация БД**: Используются индексы `GIN` для полнотекстового поиска и `similarity` для ранжирования результатов.
- **GZip**: Все ответы API сжимаются для экономии трафика.
